# 储能启发式算法

储能启发式调度算法的 Python 实现，按《储能启发式调度算法设计》分两遍计算：

1. **第一遍：容量效益**。从第 1 周到第 52 周逐周进行，找出储能能让火电"全周可行地少开 k 台"的最大 k。
2. **第二遍：消纳**。在第一遍得到的 SOC 轨迹和剩余弃电基础上，全年按时间顺序吸收弃电。

两遍都按 8760 小时、1 小时分辨率计算，SOC 全年连续。第一遍全部跑完后才开始第二遍。

## 快速开始

```bash
pip install -r requirements.txt

python -m esh demo examples/demo              # 生成示例数据（已附在仓库中）
python -m esh run examples/demo -o results    # 基准方案 + 环形年对比方案
python -m pytest -q                           # 运行测试
```

`--mode base|ring|both` 用于选择方案，默认 `both`，即两种都跑并比较。示例数据下全年计算约 3 s。

## 输入数据

输入为一个目录，包含以下文件：

| 文件 | 内容 |
|---|---|
| `timeseries.csv` | 逐时 `load, wind, solar, nuclear, import, hydro`（MW）。净负荷 = 负荷 − 风电 − 光伏 − 核电 − 外来电净受入 − 水电 |
| `units.csv` | 火电机组 `name, capacity, pmin, coal, must_run, must_run_weeks`。`must_run_weeks` 形如 `0-10;45-51`（周序号从 0 开始，例如供暖季热电联产），留空表示全年 |
| `storages.csv` | 储能 `name, power, energy, eta_rt, soc_min, soc_max, self_discharge_day`。时长小于 9 h 为日储能，否则为周储能 |
| `config.json` | `load_reserve_rate`（负荷备用率）、`accident_reserve_rate`（事故备用率） |

`examples/demo/` 是一套虚构的省级系统示例数据，只用于演示，不代表任何真实电网。

## 导入 GTDS 数据

`esh/gtds.py` 把 HUST_GTDS 运行模拟的 Excel 转成上面的输入目录：

```bash
python -m esh gtds --units 机组参数表.xlsx --plants 电站出力一览表.xlsx \
                   --load-dir 日历负荷所在目录 --system 西南 -o data/xinan
python -m esh run data/xinan -o data/results_xinan
```

- 负荷 = 系统表"日历负荷"对应的标幺曲线 × 负荷表"年Pmax"
- 风电、光伏、水电取各电站 G 表（发电出力）+ U 表（调峰弃电），即弃电前的可发出力；只计入有有效机组的电站
- 火电：煤电按"台数"展开，最小出力 = 单机容量 × 技术出力，按燃料单耗排序；燃气按 GTDS 特性表为启停调峰（最小出力 0，无煤耗），排在煤电之后；"其他"电源按必开处理
- 储能：同类合并，功率 = 单机容量 × 台数，效率取电站表"储能效率"；"储能库容"是满功率充电时长（GTDS 发电库容 = 库容 × η），故储能侧容量 = 功率 × 库容 × √η
- 备用：负荷备用取负荷表"负荷备用"，事故备用默认取"事故旋转"（`--accident-rate`）
- 保安开机：加 `--security` 时，取系统表"保安开机"作为在运火电容量下限占火电总装机的比例（`min_online_ratio`），开机台数和 k 的搜索都受此下限约束
- 煤电全开：加 `--coal-must-run` 时煤电全部必开，对应 GTDS 模拟结果中煤电全年基本全开、多数时段压在技术最小出力的运行方式
- 与 GTDS 储能出力对比：`python -m esh compare-gtds --storage 储能电站出力一览表.xlsx data/results_xinan/base`，输出年度指标、月度放电量和日内平均出力曲线（`compare_*.csv`）
- 系统内各节点按一个整体计算（不考虑输电约束），未计外送/受入；弃电率分母包含水电

## 代码结构与设计文档对应

| 模块 | 对应设计 |
|---|---|
| `esh/model.py` | 输入数据与参数；储能分类、η_c = η_d = √η、每小时自损耗、前瞻窗口（日储能 24→48→72 h，周储能 24→…→168 h）；调用顺序为短时优先、同类内效率优先 |
| `esh/commitment.py` | 开机优先级（必开机组在前，其余按煤耗）；负荷备用与事故备用；容量线与最小出力线；初始 N 与 k₀ |
| `esh/waterfill.py` | 灌水法：充电按弃电深度削谷，放电按净负荷削峰，精确求解水位 |
| `esh/state.py` | 每种储能的 P_ch、P_dis、SOC 数组，以及试算所需的快照和撤销 |
| `esh/pass1.py` | 第一遍：试算候选 k → 确定放电 → 按时间从早到晚配对充电（窗口可跨入上周，逐步扩大）→ SOC 与功率检查 → 搜索 k；保供模式；环形年 |
| `esh/pass2.py` | 第二遍：逐段剩余弃电充电，放电区间从本段充电结束到下一段弃电开始，削峰放电，放不完的延到下一个区间 |
| `esh/validate.py` | 校验：电量平衡、火电不越线、SOC 递推一致且在上下限内、年末 SOC 等于年初、功率不越限 |
| `esh/scheduler.py` | 总流程：第一遍（环形年迭代至收敛）→ 第二遍 → 校验 |

### 实现要点

- **SOC 记账**：`lift = SOC − SOC 下限`。一对配对 (c, d, E) 在 [c, d) 上抬高 SOC，抬高量为 E·η_c·ρ^(τ−c)，其中 ρ = 1 − σ_h。自损耗是线性的，各配对可以直接叠加。
- **一次配对的检查**：先用灌水法分配窗口内的充电量，再检查容量。如果超过 SOC 上限，就把本次电量等比缩小到刚好满足；SOC 已顶满时刻之前的小时不再用于充电，剩余需求在顶满时刻之后或更大的窗口里继续找。
- **第一遍最小出力线**：本周用候选 k 对应的 N−k 台的线，上一周用已确定的 k_{t−1} 的线。每个候选 k 都从本周开始前的快照重新试算。
- **保供模式**：k = 0 仍配不满时，只对没配满的需求放开火电充电，充电上限提高到容量线。仍补不上的部分记为缺电量。
- **环形年**：第 1 周可以绕回上一轮 12 月末的剩余弃电，跨年配对的电量即为年初 SOC。12 月的开机结果和预留不再变化时停止迭代。
- **第二遍电量**：在 SOC 与功率约束下二分搜索每段弃电能充入的最大电量。电量用 ρ^(−t) 贴现记账，充入和放出的贴现电量相等即闭合。

### 实现中的约定

以下是设计文档没有写明、代码中采用的处理方式：

- 8760 h 按 168 h 分为 52 周，最后一周并入剩余的 24 h（共 192 h）。
- 同一储能在同一小时不会既充又放；有储能放电的小时不作为充电位置。
- 第二遍不跨年，所有放电在年内完成。环形年只作用于第一遍。
- 第二遍每段弃电内，充电量也按弃电深度用灌水法分配。
- 开机要求容量线 ≥ max(净负荷, 最小出力线)：备用留在最小出力之上，净负荷为负时也要开够机组；停机后留不出备用的候选 k 视为不可行。
